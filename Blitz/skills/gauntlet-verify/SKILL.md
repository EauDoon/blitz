# Gauntlet Verify

The loop for work that cannot afford to be mediocre or wrong, in two modes. Reference mode drives an unfinished build toward a specific shipped artifact whose bar cannot be written down. Verification mode fields isolated verifiers over heavy research whose facts must be correct without fail; `research-protocol` owns that method, this skill owns who runs it. `cold-read` owns the rubric pass on a finished artifact at ship, `frontend-taste` (its cinematic reference file) and `pitch-architect` supply domain references, `orchestrator` routes each seat to a model. This owns the formations and the loop, not the domain.

## Host capability boundary

The portable method does not require source-platform storage or orchestration. On OpenAI, read `../../setup/host-adapters/openai.md` when using the kit; staged packages carry `references/blitz-host-adapter.md`. Preserve the current host-adapted save/install path. Knowledge stores, suite records and host router references are optional configured routes, not access or write authority. Use the already authorized task log/register if present; otherwise return findings with the candidate and state the missing external write. An unavailable orchestrator uses verified native delegation or a disclosed independence gap. Dated source-account assumptions never prove installation here.

## Why a reference beats a rubric

A rubric is a lossy compression of a reference. It survives compression when the criteria are mechanical, which is why `cold-read` works on contracts, memos and backtests. It fails when the quality is experiential: a frontend that feels expensive, a deck that lands in the room, prose that does not read as generated. Written as criteria, those become "make it polished", which `meta-skill` correctly calls a defect, because nothing can fail it with a quote.

So do not write the criteria. Name a specific artifact that already clears the bar, and make the pass condition comparative rather than absolute: a judge who never saw the build cannot pick it out as the attempt.

Verification mode is the deliberate exception: its bar is statable (`research-protocol`'s kill tests), but it lives here so that one skill owns the isolated-agent machinery for both kinds of unforgiving work.

## The gates, one per mode

Reference mode runs only when all four hold.

1. **A named reference exists and is out of reach.** A specific shipped artifact, inspectable, not a category and not a style name. "Linear's settings page" passes. "Good design" does not. Neither does a house aesthetic: "the Higgsfield look" is a style `frontend-taste` already encodes in its cinematic reference file. It becomes a reference only when a particular shipped page is named and the current build is failing to match it; then the loop drives and the domain skill supplies.
2. **The bar is not statable in advance.** If you can write three quotable criteria for a finished artifact, run `cold-read` instead.
3. **The build is unfinished.** This drives generation. Once the artifact is done, the loop that applies is `cold-read`.
4. **You will actually keep pressing.** Starting the loop and accepting round one is worse than not starting, because you paid fan-out prices for a single draft.

Verification mode fires unprompted when all three hold.

1. **The answer rests on facts outside the model across several load-bearing claims.** Heavy research, due diligence, multi-source synthesis. A quick lookup or a single figure does not raise a formation; single numeric series stay with `metric-pull`.
2. **The stakes test passes.** The output feeds money, reputation or a public statement.
3. **The work is still being drafted.** A finished artifact about to ship goes to `cold-read`.

Anti-triggers, both modes: chat answers, quick lookups, one-shot drafts, work where good enough is genuinely good enough, and Gauntlet Networks, the DeFi risk manager, which is `defi-desk` territory and shares nothing with this but a word. A complaint that one post reads as generated is `house-style` plus the voice skill; this loop takes text only when it decomposes into areas that fail independently.

## Formations

Two levels. Light is the default; spend follows consequence, not effort.

| Formation | Fields | When | Cost anchor |
|---|---|---|---|
| Light | One builder or the drafting session itself, one isolated critic or verifier, one judge when the build is ready to ship | Default, and where every unprompted run starts | 100k to 150k tokens, estimated |
| Full | Builder or verifier per area or claim cluster, isolated critic, 2 to 3 judge panel or verifier quorum | the owner says full gauntlet; a prompted job passes the stakes test; or a light round ends with a blocker open | Estimate the current run from its scope and available model pricing; record actual usage only in the authorized task receipt |

Unprompted runs start light, whatever the stakes. A prompted job that passes the stakes test runs full whatever the area count: two claim clusters still get one verifier each. His word overrides either way. A loop may drop to light for a cleanup round; it never climbs silently, and names each escalation and its reason in one line. Unattended, the written ceiling stays the brake.

Both modes: pin the model on every seat and check the model each agent actually ran on, since a session's model choice does not reach workflow subagents (measured in the strategy-seed program), and freeze the artifact while the critic, the judges or the verifiers read it, because a verdict on an artifact that changed under the reader cannot be attributed to a version.

## Protocol, reference mode

### 1. Name the reference before building

Out loud, in writing, before a line is generated. The reference has to be one the owner is not currently clearing, because a reference you already match sets the bar at your own default and the loop returns nothing.

Capture five things: the reference, the single property being matched (not all of them), how a judge will see it, the formation and why, and the ceiling in rounds or tokens that step 6 will hold. A reference nobody can show the critic is a reference the critic will invent.

How to show each kind of reference (live page, motion, document, product the critic cannot run, his own past best) is in references/showing-the-reference.md. His own past best, by path, is the strongest and most underused reference.

### 2. Decompose, then fan out

Split the build into areas that fail independently: structure, visual system, motion, copy, data correctness, edge cases. One builder per area at full formation, in parallel; the drafting session plus one critic at light. Areas, not slices of the same area, or the builders converge and the fan-out buys nothing.

Name the assembler before the fan-out. The orchestrating session splices the areas into one artifact against a slot contract agreed up front. Assembly is mechanical; an unfilled slot, an orphaned block, or an edit the assembler is tempted to make is a finding for that area's builder, never something the assembler quietly patches. A finding that spans two areas is split by the assembler into one edit per owning builder.

Builders run on a workhorse seat. Only the critic and the judge pay frontier prices. Where the surface cannot spawn parallel agents, run the areas sequentially in fresh contexts; the isolation is the requirement, the parallelism is only the speed.

### 3. Critic that never saw the build

A separate context, given the artifact and the reference and nothing about how the artifact was made. A critic in the builder's context inherits the builder's satisfaction. Where the artifact runs, the critic runs it; a verified finding outranks a read one.

The critic's instructions, verbatim:

- Name the specific gap to the reference. "Worse than the reference" without a named gap is not a finding.
- Every finding maps to one area and one edit. A finding no builder can act on is commentary.
- Do not praise, do not summarize, no preamble.
- Rank by how much closing it moves the artifact toward the reference, not by how easy it is.
- Being harsh is the job. A critic that finds nothing on round one did not look.

### 4. Blind judge, the actual stop condition

Show the judge both artifacts, unlabeled, in random order, and say what the pair is: one shipped by the reference author, one an attempt to match it. Ask which is the attempt and what gave it away, every tell tagged either craft, fixable by editing the artifact, or identity, age, adoption, ecosystem, brand, which no edit reaches. Do not ask which is better, which invites diplomacy. Do not ask which one the reference author made and leave it there: a famous reference is recognized on sight, so the bare pick measures recognition, not the gap. The pick saturates; the tells carry the verdict.

| Judge says | Read |
|---|---|
| Spots the attempt and names a craft tell an edit can close | Not there. The top craft tell is the next round's brief |
| Spots the attempt but names only craft tells that do not matter | Close. Press the single property from step 1 |
| Names only identity tells, or picks the reference as the attempt, or cannot choose, or the panel splits | Done. Stop, ship it |

At full formation run 2 to 3 judges across at least two model families where the stack allows, routed through `orchestrator`; a same-family judge shares the priors that produced the gap. One judge guessing right is coin-flip evidence. Where only one model family is available, as in a Claude-only panel, use two model tiers and say the verdict is weaker. Where the reference cannot be shown, one judge holds the written spec and the verdict is weak; say so.

### 5. Loop, and report the delta

Each round: critic findings, builders fix their own area only, judges re-run (every round at full; at light, one judge when the build is ready to ship, and a craft tell from it opens another round). Report one line per round with the delta, the change in open craft tells and critic findings since the previous round, so the trend is visible. A loop whose delta stops moving is finished whatever the judge says: stop and report the trajectory.

### 6. the owner is the brake

There is no default round cap; the only cap is the ceiling written at step 1. The loop stops on the owner's call, on a judge that stops spotting his artifact by craft, or on a delta that stops moving. A round that would breach the ceiling mid-flight does not start. Unattended, the ceiling is the brake: the loop runs to it, parks with the round-by-round trajectory as the report, and ships nothing on its own. Resuming past the ceiling is his call, made on the trajectory.

### 7. Log the run

One line at the moment the loop stops: mode, formation, artifact, reference or claim set, areas, rounds, tokens, and the judge or quorum trajectory. Append it to the run log in the connected project folder; if the Windows router is reachable, follow its SESSION-START write-back rules instead; if neither is reachable, skip it and say so in the report. Never write it to Claude's built-in memory, which a background pass owns. Three logged runs per mode replace the estimated numbers in the Formations table. A loop that does not log pays for the same lesson every time.

## Protocol, verification mode

`research-protocol` runs scoping, fan-out search, and source grading in the drafting context, as always, and the drafting context runs its own self-checks first. The gauntlet runs after them, never instead of them, and without asking permission when the stakes test passes. This skill decides who runs stage 4 and seats them:

1. List the load-bearing claims, set the formation, and write the ceiling in rounds or tokens before any verifier is seated. Formation per the ladder: one isolated verifier for all claims at light, one per claim cluster at full. An unprompted run starts light and escalates to full only when its verifier leaves a blocker open, naming the escalation in one line.
2. Verifiers never see the drafting context or its reasoning, only the claims and where they came from. Each runs `research-protocol`'s stage 4 kill tests as written, the re-fetch of every live-sourced figure (test 4, defi-pm's V8) included, and labels each claim verified, reported or unverified. The seating brief also tells them which claims the draft already labels unsourced or unverified, so a declared gap is not reported as a defect, and which self-checks ran and what each found, so they re-run each one rather than trust it. For DeFi claims the brief says whether DeFi Brain tools are loaded (load via ToolSearch). If loaded, contract reads are the recompute path and provider traces follow research-protocol's grading rule; if not, or a call errors, verifiers fall back silently to explorer and primary-source reads and never halt or ask. A verifier that does not know which tools it has reverts to web search and the kill tests weaken.
3. Quorum is asymmetric, per `cold-read`: any kill with a quote or a primary-source trace stands. Survival requires the verifier to have run every test, not to have found nothing while skimming.
4. Fix or relabel, re-verify only the claims that changed, stop. Unverified claims ship only labeled, with what would settle them. The step 1 ceiling and the unattended brake apply unchanged.
5. Say when it did not run. Where no isolated verifier can be seated from the running context, run stage 4's kill tests in the drafting context and state in the deliverable that no independent verification pass ran.

## Boundaries

| Neighbor | Owns | Split |
|---|---|---|
| `research-protocol` | The research method: scoping, search, grading, the kill tests | It says what must be true; this fields the isolated agents that test it, only when the output feeds money, reputation or a public statement |
| `cold-read` | The rubric pass on a finished artifact at ship | Finished and shipping versus in flight. A finished artifact goes there even when research-heavy; after a verification run, the at-ship check is still cold-read's |
| `metric-pull` | Acquiring and reconciling numeric series | A number is pulled there; a claim built on numbers is verified here |
| `frontend-taste` (its cinematic reference file) | The dark design system and its tokens | It is the reference for frontend work, this drives the loop toward it |
| `pitch-architect` | Deck argument spine and structure | Same, for decks |
| `meta-skill` | The standard a skill is held to | It sets bars, this one chases one |
| `orchestrator` | Which model fills each seat | It routes seats to models, this decides the formation exists |
| `reasoning-core` | The analytical discipline while drafting | Continuous and internal versus blind and isolated |

## Host and project prerequisites

Start with the stated stakes and available verification capabilities. Optional data or orchestration services require current authorized access. Keep the light default and disclose any independence or evidence gap; prior routing observations are not evidence for this host.

Pairs with `research-protocol` for the method verification mode enforces, `cold-read` as the closing pass once work ships, `orchestrator` for seating, `house-style` for the prose bar, and `frontend-taste` or `pitch-architect` for the domain reference.
