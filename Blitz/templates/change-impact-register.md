# Change-impact register

Run it for every adopted change: a new file 03 version, a closed gate, a reversed decision. Each affected output is refreshed or marked stale. Nothing stays silently out of date.

| Change | Date | Decision entry (file 10) |
|---|---|---|
| | | |

| # | Output | What is stale | Change needed | Owner | Wave | State |
|---|---|---|---|---|---|---|
| 1 | | | | | | stale, refreshed, withdrawn |

Wave 1: the canonical context files. Wave 2: instructions and project skills. Wave 3: audience-facing documents, after any decision the change opened.

Check before closing: brief, requirements, model and screens use the same names, the same launch and later scope, the same users, the same units and the same permitted claims.
