# Migrate from v2OAI

v2.1OAI is a separately commissioned successor. The original v2OAI archive and manifest identities remain in Blitz/manifest.json; they identify the source, not this new release. The repository begins with sanitized v2.1 files. No original archive, private source history, personal profile or live company case is committed.

## Existing company or item

1. Preserve the current records, instruction body and source snapshot. Verify the old artifact using its own trusted digest. Do not use the v2.1 digest for a v2 archive.
2. Read the company profile and adopt only the prompts needed for the next decision. Reuse filled 00/03/09/10 records. Keep names, identities, adopted position and decision log history; never replace them with initializer output.
3. Record the adopted package version and any changed company assumptions through the current owner. A new package does not silently amend the company's position of record.
4. Add collection timing, cash floor, contribution and delivery capacity to an existing model if absent. Blank remains unknown, zero explicit. Record currency, periods and source/assumption dates.
5. Review any working-copy startup instructions and active revision after a change. Keep its parent's identity only in lineage. Recompute the copy's manifest and rerun affected checks; do not retain a claim of byte identity with an earlier revision.
6. Test the requested next task, save, reopen and resume with declared prerequisites. Actual host routing, installation and adoption require their own evidence.

The initializer only creates a new directory. It does not import, merge or migrate existing records, and refuses an occupied destination.

## Compatibility

The 25 method folder identities and four core record names remain. Personal voice guidance now asks for an explicitly supplied style brief or approved examples; it does not emulate a bundled personal profile. Optional host role suggestions are not an installed-account inventory.

The Blitz compiler/opener/item-exporter interfaces and 17-file source-set shape remain. Generated filenames now use v2.1OAI, so saved v2 references must be updated only when that host application is explicitly authorized. Company guidance is included in Shared, and new local scripts/templates in the runtime. Builder tests, answer keys, historical review notes and worked examples stay in the master/repository rather than the runtime.

Python 3.12+ is the supported release-test target. Runtime generation and atomic directory publication support Windows and Linux. The inherited no-replace publication helper fails closed on unsupported platforms. Windows native symlink cases can be blocked by OS privilege; Linux CI exercises them. No package pass proves every imported optional script's external dependencies or arbitrary host behavior.

Export contract schema 1 and archive manifest schema 2 remain compatible. CSV scoping is an opt-in preparation tool before the existing exporter, not a silent schema change. File allowlisting still requires content and permission review. A source projection preserves source hash/revision/filter and selected columns without bundling the raw mixed dataset.

## Rollback

Stop using the new package and reopen the preserved original with its trusted digest. Preserve company decisions and legitimate working-copy changes independently; do not restore blank templates over them. Reverse host application only when authorized, using the saved exact prior instructions/sources. This release performs no host installation to undo.
